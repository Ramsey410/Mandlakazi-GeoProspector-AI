**01 — OVERVIEW**

# **Overview**

**This guide provides a concrete, step-by-step process for building a real southern African mineral occurrence training dataset and a trained Random Forest (RF) classification artifact for use in** GeoProspectorAI**'s automated prospectivity pipeline. The trained model is the core AI component that converts per-pixel feature stacks into High / Moderate / Low mineral potential labels.**

**The guide covers every stage: where to get real ground-truth occurrence data, how to acquire and preprocess the matching satellite imagery, how to engineer the feature layers, how to label and balance the training samples, how to train and validate the RF model, and how to serialise and version it for production use.**

**⚠️ Prerequisite skills: This guide assumes working knowledge of Python, GDAL/Rasterio, GeoPandas, and scikit-learn. A Google Earth Engine (GEE) account is required for cloud-based imagery access (free to register at earthengine.google.com).**

**💻 Recommended environment: Python 3.10+, Anaconda/Mamba environment, 16 GB RAM minimum, 100 GB free disk space for raw imagery. GEE Python API (earthengine-api), rasterio, geopandas, scikit-learn, joblib, matplotlib, and seaborn.**

| **STEP 8 Generate Training Labels**                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Labels are generated by combining the known mineral occurrence points with buffered proximity zones. This is the most critical and judgement-intensive step — the quality of your labels directly determines model quality.**<br><br>**High (class 2): pixels within a buffer of known producing mines or well-documented deposits (e.g. 500 m for point sources; the actual deposit polygon where available from SAMINDABA).**<br><br>**Moderate (class 1): pixels between 500 m and 5 km of known occurrences, intersecting favourable lithology (mafic/BIF) and with structural lineament density above the 75th percentile.**<br><br>**Low (class 0): pixels more than 15 km from any known occurrence, on lithology coded as granite/sediment (non-mineralising), and with low lineament density.**<br><br>**Use stratified random sampling to draw training points from each class: aim for a minimum of 500 points per class, balanced across the study area.** |

**05 — QUALITY GATES**

# **Model Quality Gates**

**The following checks must pass before any model artifact is promoted to production. Record results in the metadata sidecar JSON.**

| **Quality Check**                                 | **Minimum Threshold**         | **Action if Failed**                                           |
| ------------------------------------------------- | ----------------------------- | -------------------------------------------------------------- |
| **Held-out test weighted F1-score**               | **≥ 0.80**                    | **Augment training labels; tune hyperparameters**              |
| **High class recall (known deposits found)**      | **≥ 0.75**                    | **Add more positive (High) samples; reduce buffer distance**   |
| **Low class precision (false alarm rate)**        | **≥ 0.70**                    | **Tighten Low-class geographic exclusion criteria**            |
| **Feature importance: IOI + MMI + GEOLOGY > 40%** | **≥ 40% combined**            | **Investigate data leakage; check index computation**          |
| **Training sample balance (class ratio)**         | **No class < 25% of dataset** | **Oversample minority class with SMOTE or add more points**    |
| **Artifact SHA-256 checksum verified**            | **Must pass**                 | **Re-export model artifact; never deploy unverified checksum** |

**This guide should be read alongside the** GeoProspectorAI **Software Design Document and PRD. All model versions, training dataset versions, and quality gate results must be recorded in the** GeoProspectorAI **job audit log system for each production inference run.**
