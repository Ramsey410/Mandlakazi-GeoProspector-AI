## 01 — Overview & Design Philosophy

### Overview and Design Philosophy

The v1.0 Training Dataset Guide produced a static Random Forest artifact: trained once, versioned, and deployed. This guide advances the model to a self-improving system — one that gets better with every inference run, every field validation result, and every new geophysical survey ingested, without requiring manual retraining by a data scientist.

#### What Changes from v1.0

| **Dimension**   | **v1.0 (Static RF)**                                                      | **v2.0 (Self-Improving RF)**                                                                                                                 |
| --------------- | ------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| **Features**    | **4 spectral indices + slope + lineament density + land cover + geology** | **All v1.0 features + magnetic anomaly + Bouguer gravity + ERT resistivity + borehole lithology + 3D structural dip/strike**                 |
| **Training**    | **One-time batch train from MRDS + CGS data**                             | **Continuous retraining loop triggered by field feedback and drift detection**                                                               |
| **Evaluation**  | **Held-out test set, static**                                             | **Adversarial Evaluator Agent reconciles predictions against drill core, geochemistry, and geophysical survey results in near-real time**    |
| **Evolution**   | **Manual version bump by data scientist**                                 | **Automated Evolution Agent proposes harness and hyperparameter changes; human analyst approves before promotion**                           |
| **Meta-level**  | **None**                                                                  | **Meta-Evolution Agent learns which evolution strategies work best for each geological province / commodity type**                           |
| **Audit trail** | **JSON sidecar per model version**                                        | **Immutable append-only log: every inference, every feedback event, every retrain, every evolution step is recorded and linked to a job ID** |

## 02 — Expanded Feature Schema

### Expanded Feature Schema: Adding Geophysical Layers

The uploaded image identifies four additional data integration pillars beyond remote sensing: surface geological mapping with structural measurements, geophysical surveys (ERT and seismic), magnetic and gravity data types, and borehole geophysical logging. Each maps to new feature columns in the training dataset.

#### New Geophysical Features (v2.0 additions)

| **Feature**               | **Type / Range**     | **Source**                                                                             | **Geological Significance**                                                                                                                                                             |
| ------------------------- | -------------------- | -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **MAG_RTP**               | **Float \[0–1\]**    | **Aeromagnetic survey (CGS EMAG2 or client-supplied)**                                 | **Reduced-to-pole magnetic anomaly. Mafic intrusives, BIF, magnetite-rich zones show strong positive anomalies. Critical for Bushveld PGM and chromite targeting.**                     |
| **BOUGUER_GRAV**          | **Float \[0–1\]**    | **Bouguer gravity anomaly grid (CGS or BGI)**                                          | **Dense mafic/ultramafic bodies produce positive Bouguer anomalies. Complements MAG_RTP to distinguish mafic intrusions from magnetic sediments.**                                      |
| **ERT_RESISTIVITY**       | **Float \[0–1\]**    | **Electrical resistivity tomography surveys (client-supplied or open regional grids)** | **Low resistivity zones indicate conductive mineralisation (sulphides, graphite), hydrothermal fluid pathways, or clay alteration. Near-surface 0–50 m depth.**                         |
| **SEISMIC_DEPTH_STRUCT**  | **Float \[0–1\]**    | **2D/3D seismic interpretation (depth to key reflectors, normalised)**                 | **Fills structural information gap between boreholes. Identifies depth to mineralised horizons, fault offsets, and fold axes not visible at surface.**                                  |
| **BOREHOLE_LITHO_ENCODE** | **Integer \[0–10\]** | **Borehole logs (CGS prospecting borehole DB or client drill logs)**                   | **Most direct ground-truth feature. Lithology intersected at depth encoded per unit type (ultramafic=8, mafic=7, BIF=6, etc.). Sparse but high-information-value.**                     |
| **STRUCT_DIP_DEG**        | **Float \[0–90\]**   | **Field compass measurements / structural GIS layer**                                  | **Dip angle of foliation/bedding from structural data. Steeply dipping mafic units often control PGM and chromite reef geometry.**                                                      |
| **STRUCT_STRIKE_ENCODE**  | **Float \[0–1\]**    | **Field compass measurements / structural GIS layer**                                  | **Strike direction encoded as sin/cos pair to preserve circular geometry. Structural corridors often control gold and base metal mineralisation.**                                      |
| **GEOPHYS_SURVEY_FLAG**   | **Binary {0,1}**     | **Metadata**                                                                           | **Indicates whether a pixel falls within the coverage footprint of a geophysical survey (1) or relies on regional interpolated data (0). Used as a confidence weight during training.** |

Data acquisition note: MAG_RTP and BOUGUER_GRAV regional grids for South Africa are available from the CGS geophysics division and the South African Airborne Geophysical Database. Client-supplied ERT and seismic data must be georeferenced and resampled to the 30 m reference grid before ingestion. Borehole data is typically sparse — treat BOREHOLE_LITHO_ENCODE as a high-weight label-confirmation feature rather than a universally available input.

## 03 — Self-Improvement Architecture

### Self-Improvement Architecture

**The self-improving system is structured as three concentric loops, directly mapping the Harness Evolution Loop paper's Worker-Evaluator-Evolution Agent pattern to the** GeoProspectorAI **geoscience domain.**

#### The Three Loops

| **Loop**                                    | **Runs**                                 | **Trigger**                                                               | **Output**                                                                                                                                |
| ------------------------------------------- | ---------------------------------------- | ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| **Inner — Inference & Feedback**            | **Every GeoProspectorAI job**            | **New AOI submitted**                                                     | **Prediction + confidence map stored; feedback slot opened for field results**                                                            |
| **Middle — Harness Evolution (Retraining)** | **Weekly or on drift detection**         | **Field validation data received OR model drift score exceeds threshold** | **Improved RF model artifact; new version promoted if quality gates pass**                                                                |
| **Outer — Meta-Evolution**                  | **Monthly or after N retraining cycles** | **Sufficient evolution history accumulated across geological provinces**  | **Improved evolution strategy (retraining hyperparameters, feature selection policy, evaluation criteria) applied to future inner loops** |

## **Component Mapping: Paper →** GeoProspectorAI

| **Sylph.AI Paper Component**     | **GeoProspectorAI Implementation**                                                                                                                                                                                                                                                                                                              |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Worker Agent (WH)**            | **RF Inference Pipeline — runs pixel-wise classification on each submitted AOI's feature stack, produces prospectivity map + per-pixel confidence scores**                                                                                                                                                                                      |
| **Evaluator Agent (V)**          | **Ground-Truth Reconciliation Service — when field drill results, geochemical assays, or geophysical survey results are uploaded for a previously predicted AOI, it compares prediction vs. reality and computes a structured diagnostic report (miss rate, false alarm rate, confidence calibration error)**                                   |
| **Evolution Agent (E)**          | **Automated Retraining Service — reads the full reconciliation history, identifies systematic failure patterns (e.g. consistently underestimating chromite in ERT-surveyed zones), proposes updated training sample weights, feature selection, and hyperparameters, then executes a retraining run and submits the result for human approval** |
| **Evolution Blueprint (Λ)**      | **The full pipeline configuration: initial model version, evaluator scoring criteria, retraining triggers, feature engineering parameters, and approval workflow rules**                                                                                                                                                                        |
| **Meta-Evolution Agent (Emeta)** | **Province-Level Strategy Optimiser — across multiple geological provinces (Bushveld, Witwatersrand, Kaapvaal Craton, Zimbabwe Craton), learns which evolution strategies converge fastest for each geological setting and commodity type**                                                                                                     |
| **Harness (H)**                  | **Every piece of the GeoProspectorAI ML pipeline except the RF model parameters themselves: feature preprocessing transforms, index band ratios, normalisation bounds, class weighting scheme, prediction threshold, confidence calibration isotonic regression**                                                                               |

<div class="joplin-table-wrapper"><table><tbody><tr><th><p><strong>STEP 19 Implement Model Drift Detection</strong></p></th></tr><tr><td><p><strong>Between full retraining cycles, monitor the live model for distribution shift — cases where the incoming AOI feature distributions diverge from the training data distribution. ## 05 — Quality Gates and Acceptance Criteria

### Quality Gates and Acceptance Criteria

All quality gates from v1.0 remain in force. The following additional gates apply to every evolution cycle before a new model version can be promoted.

| **Gate**                                     | **Threshold**                                 | **Measured By**                        | **Action if Failed**                                                                        |
| -------------------------------------------- | --------------------------------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------- |
| **Weighted F1 on held-out validation set**   | **≥ 0.82 (v2.0 raises bar from v1.0's 0.80)** | **scikit-learn classification_report** | **Reject proposal; Evolution Agent must revise**                                            |
| **High class recall (known deposits)**       | **≥ 0.75**                                    | **Per-class recall**                   | **Upweight High-class samples; reduce buffer distance**                                     |
| **False alarm rate (Low predicted as High)** | **≤ 0.15**                                    | **EvaluatorReport.false_alarm_rate**   | **Increase min_samples_leaf; tighten Moderate/High boundary**                               |
| **Confidence calibration error (ECE)**       | **≤ 0.10**                                    | **Isotonic regression calibration**    | **Apply post-hoc calibration via CalibratedClassifierCV**                                   |
| **PSI drift score on held-out OOD region**   | **≤ 0.25 per feature**                        | **population_stability_index()**       | **Flag region as out-of-domain; do not deploy without more training data from that region** |
| **Feature importance consistency**           | **IOI+MMI+GEOLOGY+MAG_RTP > 40% combined**    | **RF feature_importances_**            | **Check for data leakage; validate index computation pipeline**                             |
| **Human analyst approval**                   | **Mandatory — 100%**                          | **Audit log APPROVAL event**           | **No promotion without explicit approval + written comment**                                |
| **Audit log chain integrity**                | **SHA-256 hash chain unbroken**               | **Hash chain verification tool**       | **Halt all promotion activity; investigate log tampering**                                  |

## 06 — Deployment Architecture

## 07 — Dataset and Model Versioning Strategy

### Dataset and Model Versioning Strategy

Because the training dataset grows with every field observation, and because the model is retrained from that growing dataset, both the dataset and model must be versioned together. A model version is only meaningful in the context of the exact dataset version it was trained on.

#### Versioning Convention

**Model artifact filenames follow the pattern:** GeoProspectorAI**\_rf_v{MODEL}.{DATASET}.joblib Example:** GeoProspectorAI**\_rf_v2.3.d14.joblib = model version 2.3 trained on dataset version 14. The metadata JSON sidecar records the full dataset provenance: which occurrence sources, which imagery dates, how many samples per class, and the SHA-256 of the training CSV.**

| **Version Event**                    | **Who Triggers**                                                   | **What Changes**                                                                 | **Audit Log Event**             |
| ------------------------------------ | ------------------------------------------------------------------ | -------------------------------------------------------------------------------- | ------------------------------- |
| **Dataset version bump**             | **Automatic — on each approved field observation batch ingestion** | **New samples appended to training CSV; new SHA-256 computed**                   | **DATASET_VERSION_BUMP**        |
| **Model patch version bump (x.x.N)** | **Automatic — on successful retraining with minor harness change** | **Hyperparameter change only; same feature schema**                              | **PROMOTION**                   |
| **Model minor version bump (x.N.0)** | **Human analyst approval required**                                | **New feature added (e.g. new geophysical layer)**                               | **PROMOTION + SCHEMA_CHANGE**   |
| **Model major version bump (N.0.0)** | **Human analyst approval required**                                | **Breaking change: feature removed, schema reordered, label definition changed** | **PROMOTION + BREAKING_CHANGE** |
| **Blueprint version bump**           | **Meta-Evolution Agent + analyst approval**                        | **Evolution strategy registry updated for one or more provinces**                | **BLUEPRINT_UPDATE**            |
